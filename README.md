## 기능 요구사항

- 로또 구입 금액을 입력하면 구입 금액에 해당하는 로또를 발급해야 한다.
- 로또 1장의 가격은 1000원이다.
- 로또 당첨 번호를 받아 일치한 번호 수에 따라 당첨 결과를 보여준다.
- 2등을 위한 보너스볼을 추첨한다. 
- 당첨 통계에 2등을 추가한다. 
- 2등 당첨 조건은 당첨 번호 5개 일치 + 보너스 볼 일치다.
- 현재 로또 생성기는 자동 생성 기능만 제공한다. 사용자가 수동으로 추첨 번호를 입력할 수 있도록 해야 한다.
- 입력한 금액, 자동 생성 숫자, 수동 생성 번호를 입력하도록 해야 한다.

## 필요한 도메인 객체

### lotto
- `LottoNumber`: 로또 번호 (1~45 범위의 원시값 포장)
- `LottoNumbers`: 로또 번호 6개를 담는 일급 컬렉션
- `Lotto`: 로또 한 장 (LottoNumbers를 포함)
- `Lottos`: 구매한 로또들을 담는 일급 컬렉션
- `LottoNumberGenerator`: 랜덤 로또 번호 생성기
- `WinningLotto`: 당첨 번호와 보너스 번호를 가진 객체
- `Rank`: 당첨 등수를 나타내는 Enum (1등~5등, 낙첨)
- `LottoResult`: 당첨 결과 통계를 담는 객체

### purchase
- `Money`: 금액을 나타내는 원시값 포장 객체
- `LottoFactory`: 수동/자동 로또 생성 팩토리
- `PurchaseCalculator`: 구매 금액으로 로또 개수 계산

## 고민한 점

### 일급 컬렉션 설계
- `LottoNumbers`는 `List<LottoNumber>`를 감싸는 일급 컬렉션으로 설계하였으며, 로또 번호가 **항상 6개이고 중복되지 않으며 정렬된 상태**임을 보장하도록 구현하였습니다.
- `Lottos`는 `List<Lotto>`를 감싸는 일급 컬렉션으로, 사용자가 구매한 로또 목록을 하나의 도메인 개념으로 표현하고 불변으로 관리하도록 설계하였습니다.
- 컬렉션을 그대로 노출하기보다는 일급 컬렉션을 사용함으로써, **컬렉션에 대한 검증 로직과 비즈니스 로직을 한 곳에서 관리할 수 있도록 하는 점을 중점적으로 고민하였습니다.**

### 로또 도메인 객체 구조화
- 로또 도메인을 `LottoNumber` → `LottoNumbers` → `Lotto` → `Lottos`의 계층 구조로 나누어 설계하였습니다.
- 각 객체가 자신의 상태를 스스로 검증하도록 책임을 명확히 하고, 상위 객체가 하위 객체의 내부 구현에 의존하지 않도록 설계하고자 하였습니다.
- 모든 도메인 객체는 불변 객체로 구현하여, 생성 이후 상태 변경으로 인한 부작용을 최소화하려고 하였습니다.
- 당첨 등수와 상금 정보는 `Rank` enum을 통해 하나의 타입으로 관리함으로써, **등수에 대한 규칙과 데이터를 분산시키지 않도록 고민하였습니다.**

### 책임 분배
- 도메인 객체는 자신의 상태를 검증하고, 해당 도메인과 관련된 비즈니스 로직만 수행하도록 책임을 제한하였습니다.
- `WinningLotto`는 로또 번호 비교를 통해 당첨 여부를 판단하고, 그 결과로 `Rank`를 반환하는 책임을 가지도록 설계하였습니다.
- `LottoFactory`는 수동/자동 로또 생성에 대한 책임을 가지며, 생성 방식이 변경되더라도 다른 도메인 객체에 영향을 주지 않도록 역할을 분리하였습니다.
- `LottoVendingMachine`은 전체 흐름을 제어하는 역할만 담당하고, 실제 비즈니스 로직은 도메인 객체에 위임하도록 설계하였습니다.
- View는 입출력만을 담당하도록 분리하여, 도메인 로직이나 내부 구현에 대해 알지 못하도록 구성하였습니다.
