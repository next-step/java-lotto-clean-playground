## 이번 리팩토링에서 신경 쓴 부분

### 1. 사용하지 않는 필드 제거 

- 사용하지 않는 변수나 생성자에서만 사용하는 변수들은 필드변수로 만들지 않는다는 기준으로 리팩토링 했습니다!

### 2. 테스트 코드를 작성해야 하는 클래스의 기준

- 테스트코드를 해야하는 클래스는 예외가 발생할 수 있는 클래스는 반드시 테스트를 해야하고, 그 다음에 해당 클래스에서 계산 로직이 있는 경우에는 테스트코드를 작성하는 것이 좋다고 생각합니다!

- 예를들어 당첨된 로또의 상금을 더하는 경우 내가 원하는 결과가 정말로 나오는지 확인이 필요하므로, 해당 클래스안에 메서드가 통계나 계산을 처리한다면 테스트코드를 작성해야한다고 생각합니다!

### 3. 단순 위임만 하는 클래스 정리

이번에 리팩토링하면서 단순 위임만 하는 부분을 최대한 줄여봤습니다. 분리는 하되, 분리하는 이유가 명확하도록 설계하는 걸 목표로 했습니다!

- 도메인끼리 getter를 사용하는 것을 없애고, 해당 도메인이 처리해서 메서드 반환형태로 변경했습니다!
- `LottoRankTable`이 외부에서 만들어진 `map`을 받는 것이 아닌 `List<LottoMatchResult>`를 받아 `LottoRankTable` 내부에서 `map` 형식으로 변경하도록 했습니다!

### 4. 불필요한 래퍼 클래스를 기본형으로 변경

불필요하게 사용한 래퍼클래스들은 기본형으로 변경하는 것도 함께 진행해봤습니다!

- 불변이냐 아니냐가 아니라, **null이 될 수 있는가**, **컬렉션에 담아야 하는가** → 이 기준으로 둘 중 하나라도 해당하는 경우에만 래퍼 타입(불변 객체)을 적용하고, 나머지는 기본형으로 변경했습니다!

### 5. 2단계 리팩토링과 3단계 병행 진행

- 2단계 리팩토링과 함께 3단계(2등 당첨)도 함께 진행해봤습니다!
