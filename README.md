# 4단계 요구사항 정리

---

## 기능 요구사항

- [x] 로또 구입 금액을 입력하면 구입 금액에 해당하는 로또를 발급해야 한다.
- [x] 로또 1장의 가격은 1000원이다.
- [x] 배열 대신 컬렉션을 사용한다.
- [x] 줄여 쓰지 않는다(축약 금지).
- [x] 함수(또는 메서드)의 길이가 10라인을 넘어가지 않도록 구현한다.
- [x] 함수(또는 메서드)가 한 가지 일만 하도록 최대한 작게 만들어라.
- [x] 2등을 위한 보너스 번호를 추첨한다.
- [x] 당첨 통계에 2등을 추가한다 (당첨 번호 5개 일치 + 보너스 볼 일치).
- [x] 사용자가 수동으로 구매할 로또 개수와 번호를 입력할 수 있도록 한다.
- [x] 수동 구매와 자동 구매를 함께 처리하고 그 결과를 출력한다.

## 새로운 프로그래밍 요구사항

- [x] 모든 원시 값과 문자열을 포장한다.
- [x] 일급 컬렉션을 쓴다.

## 기존 프로그래밍 요구사항

자바 코드 컨벤션을 지키면서 프로그래밍한다.
기본적으로 Java Style Guide을 원칙으로 한다.
indent(인덴트, 들여쓰기) depth를 2를 넘지 않도록 구현한다. 1까지만 허용한다.
예를 들어 while문 안에 if문이 있으면 들여쓰기는 2이다.
힌트: indent(인덴트, 들여쓰기) depth를 줄이는 좋은 방법은 함수(또는 메서드)를 분리하면 된다.
3항 연산자를 쓰지 않는다.
else 예약어를 쓰지 않는다.
else 예약어를 쓰지 말라고 하니 switch/case로 구현하는 경우가 있는데 switch/case도 허용하지 않는다.

## 사용할 클래스의 종류 및 특징 정리

### 도메인

#### Money
1. 입력금액을 저장한다.
2. 로또 횟수정보를 환산하여 저장한다.
3. 입력과정에서 예외처리를 수행한다.

#### PurchaseCount
1. 전체 구매 가능 횟수 중 수동 구매 횟수와 자동 구매 횟수를 분리하여 저장한다.
2. 수동 구매 횟수가 음수이거나 전체 횟수를 초과하는지 검증한다.

#### RandomLottoGenerator
원소가 6개인 중복 없는 랜덤 숫자를 생성하여 `Lotto` 객체로 반환한다.

#### Lotto
1. `LottoNumber` 6개를 리스트 형태로 감싸는 일급 컬렉션이다.
2. 생성 시 로또 번호의 개수가 6개인지, 중복되는 숫자가 없는지 검증한다.

#### WinningLotto
1. 당첨 번호(`Lotto`)와 보너스 볼(`LottoNumber`)을 조합하여 저장한다.
2. 보너스 볼이 당첨 번호와 중복되는지 검증한다.
3. 사용자의 로또를 전달받아 일치 개수와 보너스 일치 여부를 파악한 뒤 `Rank`를 반환한다.

#### LottoCalculator
1. `EnumMap`을 활용하여 각 `Rank`별 당첨 횟수를 기록한다.
2. 기록된 당첨 통계를 바탕으로 전체 상금액을 구하여 수익률을 계산한다.

#### LottoNumber
1. 1~45 범위의 로또 숫자를 나타내는 원시 값 포장 객체(VO)이다.
2. 생성 시 숫자의 범위를 검증하며, 동등성(equals/hashCode)을 보장한다.

#### Lottos
1. 로또(`Lotto`) 리스트를 감싸는 일급 컬렉션이다.
2. `WinningLotto`를 인자로 받아 내부의 로또들을 모두 대조하고, 통계가 기록된 `LottoCalculator`를 반환한다.

#### Rank (Enum)
1. 일치 횟수, 보너스 볼 일치 여부, 상금 정보를 상수로 관리한다.
2. 일치 횟수와 보너스 매치 여부를 전달하면 조건에 맞는 해당 `Rank` 객체를 반환한다.

### 뷰

#### InputView
1. 구입 금액, 당첨 번호, 보너스 볼, 수동 구매 개수, 수동 구매 번호를 차례대로 입력받는다.

#### ResultView
1. 수동 구매 장수와 자동 구매 장수를 출력한다.
2. 구매한 로또 번호들의 리스트를 출력한다.
3. 2등(보너스 볼 일치)을 포함한 당첨 통계와 총 수익률을 출력한다.

### 컨트롤러

#### Application
1. 도메인 객체와 뷰 사이의 데이터 흐름을 제어한다.
2. 사용자 입력 시 예외(IllegalArgumentException)가 발생하면, 정상적인 값이 입력될 때까지 재요청하는 예외 처리 루프를 수행한다.
3. 문자열 입력을 도메인 객체로 변환하고, 도메인 객체를 출력용 DTO 형태(List)로 변환하는 어댑터 역할을 수행한다.

# 예외 처리

- 구입금액이 빈 값이거나 숫자가 아닐 때
- 구입금액이 1000원보다 작을 때
- 구입금액이 1000원 단위가 아닐 때
- 수동 구매 개수가 숫자가 아니거나 음수일 때
- 수동 구매 개수가 총 구매 가능 개수보다 클 때
- 당첨 번호 및 수동 로또 번호가 적절한 형식(쉼표 구분)이 아닐 때
- 당첨 번호, 수동 로또 번호에 중복된 번호가 있을 때
- 로또 번호가 1~45 범위가 아닐 때
- 당첨 번호, 수동 로또 번호의 개수가 6개가 아닐 때
- 보너스 볼이 숫자가 아니거나 1~45 범위가 아닐 때
- 보너스 볼이 기존 당첨 번호 6개와 중복될 때
