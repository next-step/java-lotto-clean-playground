# 🍀 로또
> 입력한 금액만큼 로또를 사고 당첨 결과를 확인하는 간단한 프로그램

## 1단계

### 📝 기능 요구사항
✅ 로또 구입 금액을 입력하면 구입 금액에 해당하는 로또를 발급해야 한다.

✅ 로또 1장의 가격은 1000원이다.


### 💻 구현 전략
1. MVC 패턴을 적용 - view, model, controller로 분리
2. `lotto 클래스` - 생성한 6자리 로또 번호를 리스트를 필드로 저장
3. `lottos 클래스` - 구매 수량만큼 로또를 발급하고 로또 번호 리스트를 필드로 저장
4. 전략 패턴을 적용해서 로또 번호 자동 생성 기능을 숫자 생성으로 추상화하여 주입


---
## 2단계

### 📝 기능 요구사항
✅ 로또 당첨 번호를 받아 일치한 번호 수에 따라 당첨 결과를 보여준다.


### 💻 구현 전략

1. 당첨결과를 enum 타입으로 저장하여 사용
2. 입력 형식에 관한 예외처리는 view에서, 비즈니스에 특화된 제한사항들은(ex.로또 번호는 6자리 이다..) 도메인에서 발생시킨다  
   ➡️ 입력 구매 금액과 입력 우승 번호를 따로 일급 컬렉션을 만들어 예외발생 및 요구사항 처리  
   ➡️ 잘못된 입력시 재입력 받도록 회복하는 처리를 한다
3. 구매한 로또의 당첨결과를 저장할 클래스를 만들고, 수익 계산

### 🤔고민한 부분
1. 당첨번호를 뜻하는 `WinningNumbers 클래스`도 6자리 로또 번호인데 자동생성 로또 번호를 뜻하는 `lotto 클래스`와 분리할 필요가 있을까?    
   ➡️  `lotto 클래스`에서는 `WinningNumbers 클래스`와 달리 우승자를 가려내는 로직이 필요하기에 분리를 하였지만 _**둘다 결과적으로 6자리의 로또 번호를 뜻하기 때문에 `lotto 클래스`로 합치자**_

## 3단계

### 📝 기능 요구사항
✅ 2등을 위한 보너스볼을 추첨한다.

✅ 당첨 통계에 2등을 추가한다. (2등은 5개 일치 + 보너스볼 일치)


### 💻 구현 전략

1. 보너스 볼 일급 컬렉션을 만들어 우승번호와 중복되는 보너스 볼일 경우 예외처리   
   ➡️ 잘못된 입력시 재입력 받도록 회복하는 처리를 한다
3. 2등당첨 로직과 3등 당첨 로직을 수정 (2등은 5개+보너스볼 / 3등은 5개 매치)

## 4단계

### 📝 기능 요구사항
✅ 현재 로또 생성기는 자동 생성 기능만 제공한다. 사용자가 수동으로 추첨 번호를 입력할 수 있도록 해야 한다.

✅ 입력한 금액, 자동 생성 숫자, 수동 생성 번호를 입력하도록 해야 한다.


### 💻 구현 전략

1. Lottos 클래스에서 수동 로또를 생성하는 정적 팩터리 매서드와 자동 로또를 생성하는 정적 팩터리 매서드를 분리하여 구현

2. PurchaseAmount에서 amount필드를 autoPurchaseAmount와 manualPurchaseAmount로 필드를 분리 


### 🤔고민한 부분
1. `Lottos 클래스` 안에 수동로또필드와 자동로또필드로 구분하여 로또값들을 저장하는 것이 더 나은 선택일까?    
   ➡️  단일 리스트`(List<lotto> lottos)`로 유지하는 방식이 확장성이 더 좋은 설계 같다  
   ➡️  추후 반자동 로또 같은 요구사항이 추가된다면 필드를 또 만들어야 하고 필드를 추가하게 되면 Lottos를 사용하는 외부의 많은 로직변경이 필요하지만,  
   ➡️  단일 로또 리스트로 관리하게 되면 생성로직만 추가해 주면 되고, 외부 의존하는 로직의 변경점이 비교적 적은 것 같다
