## 이번 리팩토링에서 신경 쓴 부분

### 1. TDA 원칙 학습 및 적용

TDA (Tell, Don't Ask) 원칙을 보내주신 링크를 통해 학습해봤습니다! 먼저 TDA 원칙에 대해 제가 이해한 부분을 말씀드리겠습니다.

TDA는 "묻지 말고 시켜라"는 원칙으로, 어떤 객체의 데이터가 필요하다면 getter로 그 값을 꺼내오는 대신, 데이터가 필요한 객체에게 필요한 값을 파라미터로 넘겨주고 결과만 반환받도록 하라는 뜻으로 이해했습니다.

'왜 이렇게 하는 게 좋을까?'라는 생각이 들었는데, 실제로 코드를 고치면서 그 이유를 느꼈습니다. TDA 원칙을 지키려고 하니 자연스럽게 객체마다 책임이 자리를 잡았습니다. '이 상황에서는 getter를 써야 하는데...' → 'getter 없이 메서드를 만들어서 결과만 받자' → 자연스러운 역할 분담, 이런 흐름으로 리팩터링이 진행됐습니다. getter가 잘못된 건 아니지만, getter로 값을 외부에 내보내는 순간 그 값을 가진 객체가 담당해야 할 역할이 바깥으로 새어나가 캡슐화가 깨질 수 있다는 걸 이번에 체감했습니다. 이와 동시에 TDA원칙을 지킨다면 자연스럽게 역할분담과 캡슐화가 지켜진다는 것도 느꼈습니다.



### 2. 테스트코드 수정

- assertAll로 여러 등수(1등~MISS)를 한 테스트에서 한꺼번에 검증하던 LottoRankTableTest, LottoRankTest를 등수별 개별 테스트로 분리했습니다. 테스트 하나가 어떤 등수를 보장하는지 이름만 보고도 알 수 있도록 네이밍도 함께 정리했습니다!

### 3. 단일 책임 원칙(SRP) 적용 및 위임 객체 제거

LottoController.run()이 구매 입력부터 최종 결과 출력까지 전부 한 메서드에서 처리하고 있어서 하나의 메서드에 너무 많은 일이 몰려 있었습니다. run()은 전체 흐름을 조립하는 최상위 역할만 갖도록 하고, 각 단계는 별도의 메서드로 분리해서 메서드 하나가 하나의 일만 하도록 정리했습니다.
