## 이번 리팩토링에서 신경 쓴 부분

### 1. 스트림 학습 및 적용 연습

이번에 리팩토링을 하면서 참고하고자 다른 스터디원들의 코드도 같이 봤는데, 스트림을 적절한 곳에서 사용하면 간단하게 코드 작성을 할 수 있는 걸 보며 이번 리팩토링은 스트림을 학습 및 반복문이나 조건문 같은 경우를 스트림으로 처리하는 연습을 하며 진행해봤습니다.
(최대한 반복문 같은 경우 스트림으로 해보려고 했지만 실패한 부분들은 for문으로 처리했습니다.)

### 2. 값이 변경될 수 있는 형태로 돌아다니지 않도록 클래스로 감싸기

이번 리팩토링에 가장 필요하다고 생각했던 부분은 값들이 변경될 수 있는 형태로 돌아다니는 게 문제였다고 느꼈습니다. 그래서 최대한 감쌀 수 있는 값들은 클래스로 감싸서 전달하고,일급컬렉션도 적용해봤습니다. 동시에 이 클래스의 역할을 어디까지 설정할 것인가를 고민하며 리팩토링해봤습니다.

### 3. 메서드명·변수명·클래스명 네이밍

생각보다 시간이 오래 걸렸던 부분은 메서드명과 변수명, 그리고 클래스명을 적절하게 설정하는 것이었습니다. 이전 코드에서도 느꼈던 점인데 직관적이지 않은 변수와 클래스, 메서드가 섞이니 코드를 이해하는 데 너무 어려웠습니다. 리뷰에서 남겨주신 사이트의 내용을 통해서 네이밍도 같이 연습해봤습니다.

### 4. 클래스별 테스트 코드 분리

테스트 코드도 하나의 클래스로 몰아서 하는 것이 아닌 각 클래스마다 테스트 코드를 만드는 것이 바람직하다는 걸 느꼈습니다. 기존 코드에서는 예외가 발생하는 위치를 바로 알 수 없었지만, 클래스마다 분리해놓고 해당 클래스에서 발생할 수 있는 예외들만 모아보니 가독성도 좋아지고, 여러 테스트도 빠르게 추가할 수 있겠다고 생각했습니다.
